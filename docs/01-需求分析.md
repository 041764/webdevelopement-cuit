# 需求分析（班导师管理系统后端）

## 1. 业务对象与边界
### 1.1 核心业务对象
- 学院（College）
- 用户（User：学生/教师）
- 角色（Role：ADMIN_SCHOOL / ADMIN_COLLEGE）
- 班级（Class：含学期 term）
- 活动（Activity：报名、可审核、容量）
- 计划（Plan：包含多个 PlanItem，用于完成率统计）
- 评价（Evaluation：及明细 EvaluationDetail）

### 1.2 关键边界与假设
- 登录时前端明确选择 `user_type`，后端不做“同号自动猜测”。
- 院级/校级管理员均为教师账号；权限由角色决定。
- 开发环境使用 SQLite；后续可迁移到 PostgreSQL。

## 2. 主要用例
### 2.1 鉴权用例
- 登录：`(user_type, user_no, password)` -> `access/refresh`
- 刷新：`refresh` -> 新 `access/refresh`
- 登出：撤销某个 refresh（支持多设备）
- 查询当前用户：`/auth/me`

### 2.2 用户导入用例（CSV）
- 教师/管理员上传 CSV（含 `id,name,collegeName`）
- 系统自动创建缺失学院
- 已存在账号则更新 `name/college`
- 返回统计结果（created/updated/failed）

### 2.3 活动用例
- 教师创建活动（term、容量、requiresReview）
- 学生报名
- 若 requiresReview：教师审核通过/拒绝；否则自动通过（实现策略见系统设计）
- 容量达到后拒绝新报名（或进入候补：本期不做候补）

### 2.4 计划用例
- 学生创建计划与条目
- 条目状态变更（todo/doing/done）
- 完成率按 done/total 计算；可产生快照记录（plan_progress）

### 2.5 评价用例
- 教师对学生评价（总评 + 明细项）

### 2.6 报表用例
- 计划完成率报表（按 term/学院/班级聚合）
- 活动报名统计报表（按 term/活动）

## 3. 权限矩阵（最小版）
- STUDENT：
  - 登录/刷新/登出/自查
  - 报名活动、查看自己的报名状态
  - 维护自己的计划
- TEACHER：
  - 以上 + 创建活动、审核报名（当 requiresReview）
  - 导入用户（CSV）
  - 评价学生
- ADMIN_COLLEGE：
  - 以上 + 管理本学院范围数据（学院内用户/班级/活动）
- ADMIN_SCHOOL：
  - 全校范围管理；可不绑定学院
