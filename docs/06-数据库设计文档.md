# 数据库设计文档（SQLite 开发版）

## 1. 命名与兼容性约定
- 本项目按需求使用表名：`college`、`user`、`role` 等。
- 注意：`user`、`class` 在 PostgreSQL 中是保留/敏感标识符，迁移到 PG 时建议改名为 `app_user`、`classroom`，或统一加引号并建立视图兼容层。

## 2. 表结构（V1）
迁移脚本：`backend/src/main/resources/db/migration/V1__init.sql`

### 2.1 college
- 约束：`name` 唯一
- 用途：用户归属学院；CSV 导入时自动创建

### 2.2 user
- 字段：
  - `user_type`：`STUDENT|TEACHER`
  - `user_no`：学号/工号（CSV 字段 `id`）
  - `id`：内部数字主键（API 命名：`userId`）
  - `college_id`：可空（仅 `ADMIN_SCHOOL` 允许空，其余逻辑在应用层校验）
  - `status`：`ACTIVE|DISABLED`
- 约束：
  - `(user_type, user_no)` 唯一
- 索引：
  - `idx_user_college_id`
  - `idx_user_type_no`（通常由唯一索引覆盖）

### 2.3 role / user_role
- role.code：`ADMIN_SCHOOL|ADMIN_COLLEGE|TUTOR`（导师/普通教师仅靠 role 区分）
- 约束：不使用 CHECK 将 code 限死为固定集合（仅保留 UNIQUE）
- user_role：联合主键（user_id, role_id）

### 2.4 local_credential
- 存储输入侧：`clientSalt/clientHash`（前端传入）
- 后端建议：在服务端再做二次 hash 并存入 `server_hash`（本期仅预留字段）
- 约束：`user_id` 唯一（每个账号一份本地凭证）

### 2.5 refresh_token
- 仅存 `token_hash`（对 refresh token 明文 hash 后的结果）
- 字段：
  - `issued_at`、`expires_at`、`revoked_at`
  - `device_id`（可选）
- 索引：
  - `uq_refresh_token_hash`
  - `idx_refresh_token_user_id`
  - `idx_refresh_token_expires_at`

### 2.6 class / class_student / class_tutor
- class.term：满足 `yyyy-mm-dd-1/2`（数据库用 GLOB 做弱校验，强校验在应用层）
- class_student：每班每学生唯一
- class_tutor：每班每导师唯一

### 2.7 activity / activity_signup
- activity.class_id：活动归属班级
- activity.requires_review：0/1
- activity.capacity：可空（空代表不限制）
- activity_signup.status：`APPLIED|APPROVED|REJECTED|CANCELED`
- 约束：
  - activity_signup(activity_id,user_id) 唯一

### 2.8 plan / plan_item / plan_item_progress
- plan.owner_type：`CLASS|USER`
- plan.owner_user_id / plan.owner_class_id：二选一（数据库用 CHECK 保证与 owner_type 一致）
- plan_item.status：`todo|doing|done`
- plan_item_progress：条目进度历史（append-only）

### 2.9 evaluation / evaluation_detail
- evaluation：总评
- evaluation_detail：明细项（item_key 可作为指标编码）

## 3. 关键约束与索引清单（摘要）
- `college(name)` UNIQUE
- `"user"(user_type, user_no)` UNIQUE
- `role(code)` UNIQUE
- `user_role(user_id, role_id)` PRIMARY KEY
- `local_credential(user_id)` UNIQUE
- `refresh_token(token_hash)` UNIQUE
- `activity_signup(activity_id, user_id)` UNIQUE
- 典型查询索引：
  - `"user"(college_id)`
  - `activity(class_id,term,status)`
  - `activity_signup(activity_id,status)`
  - `plan(owner_user_id,term)`
  - `plan(owner_class_id,term)`
  - `plan_item(plan_id,status)`
  - `plan_item_progress(plan_item_id,created_at)`

## 4. SQLite -> PostgreSQL 迁移注意事项
- **自增主键**：
  - SQLite: `INTEGER PRIMARY KEY` 自带 rowid
  - PG: `BIGSERIAL` 或 `GENERATED BY DEFAULT AS IDENTITY`
- **时间类型**：
  - SQLite 多用 `TEXT` 存 ISO；PG 建议 `timestamptz`
- **布尔**：
  - SQLite 用 `INTEGER`(0/1)；PG 用 `boolean`
- **保留字**：
  - `user`、`class`：PG 需改名或加引号；推荐改名并提供视图兼容
- **约束表达式**：
  - SQLite 的 `CHECK/GLOB` 语法在 PG 需改写为正则或更严格类型校验
