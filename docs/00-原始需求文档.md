# 班导师管理系统（后端）— 原始需求文档

## 1. 背景与目标
- 面向学校/学院的班导师管理与学生事务协同，提供后端 API 供前端调用。
- 技术栈约束：Java 17 + Spring Boot + Maven + MyBatis + SQLite（开发）+ Flyway（迁移）+ JWT（鉴权）。

## 2. 用户与权限（硬性约束）
### 2.1 用户类型
- 仅两类用户：`STUDENT`、`TEACHER`。
- “管理员”本质属于 `TEACHER`，但额外拥有角色：`ADMIN_SCHOOL`（校级管理员）、`ADMIN_COLLEGE`（院级管理员）。

### 2.2 账号唯一性
- 账号唯一键：`(user_type, user_no)` 联合唯一。
- 同一 `user_no` 可同时在学生与教师重复存在（例如：同号工号/学号但不同类型）。

### 2.3 登录方式
- 登录由前端选择 `STUDENT/TEACHER`，后端以该 `user_type` 做账号定位与鉴权。

### 2.4 学院字段规则
- 除校级管理员（`ADMIN_SCHOOL`）外，所有用户必须绑定学院。
- CSV 导入时若 `collegeName` 不存在则自动创建学院记录。

## 3. 鉴权与会话（硬性约束）
### 3.1 JWT
- `access token` 有效期：6 小时（6h）
- `refresh token` 有效期：12 小时（12h）
- `refresh token` 落库：支持登出撤销（revocation）
- 允许多设备并存（同一用户可存在多个有效 refresh token），可选 `device_id` 标识设备

## 4. CSV 导入（硬性约束）
### 4.1 CSV 格式
- 标准 CSV：逗号分隔、UTF-8
- 可包含表头
- 字段：`id,name,collegeName`
  - 说明：`id` 对应账号的 `user_no`（即学号/工号）

### 4.2 导入行为
- 若账号不存在：创建用户
- 若账号已存在：更新 `name`、`college`
- 统计导入结果：新增/更新/跳过/失败（至少新增、更新、失败）

## 5. 活动（硬性约束）
- 支持活动报名、审核（可选 `requiresReview`）、容量限制（capacity）
- 暂不做签到

## 6. 计划与完成率（硬性约束）
- 计划完成率口径：按 `plan_item.status = done` 统计

## 7. 学期 term（硬性约束）
- `term` 格式：`yyyy-mm-dd-1/2`

## 8. 交付范围（本次骨架）
- 以“可运行的后端骨架”为目标：
  - 能启动服务
  - 提供 `/health`
  - 提供 Swagger UI 与 `/v3/api-docs`
- 先交付工程文档与脚本，确保前后端可对接。
