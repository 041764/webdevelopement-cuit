# 系统设计（后端）

## 1. 架构概览
- 形态：单体 Spring Boot REST 服务
- 分层（建议实现时保持最小必要）：
  - Controller（HTTP）
  - Service（业务规则）
  - Mapper（MyBatis，SQL）
  - DB（SQLite/PG）
- 迁移：Flyway 管理 schema 版本
- 文档：springdoc 暴露 `/v3/api-docs` 与 Swagger UI

## 2. 模块划分（按 API）
- Auth：登录/刷新/登出/自查
- Colleges：学院字典（导入时自动创建）
- Users：导入、查询（后续扩展）
- Classes：班级、学生/导师关联
- Activities：活动、报名、审核
- Plans：计划、条目、进度快照
- Evaluations：评价与明细
- Reports：统计聚合接口

## 3. 鉴权设计（JWT + Refresh Token 存储）
### 3.1 Token 签发
- access token：短期（6h），仅携带最小必要声明（user_id、user_type、roles、issuer、exp）
- refresh token：长期（12h），随机高熵字符串；只存 hash（`token_hash`），不落明文

### 3.2 Refresh Token 数据模型
- 支持多设备：同一用户可存在多个未撤销 refresh 记录
- 登出：对指定 refresh 记录写入 `revoked_at`
- 刷新策略（建议）：
  - 旋转：使用 refresh 换新 refresh，同时撤销旧 refresh（更安全）

## 4. 数据一致性与并发（关键点）
- 活动容量：对“批准数”加锁/事务处理，避免超卖
  - SQLite 场景建议：事务 + 查询已批准数 + 插入/更新（后续可改为乐观锁字段）
- 导入 CSV：按 `(user_type,user_no)` upsert，需保证学院创建与用户更新在同一事务中

## 5. 错误码（与 API 文档一致）
- `AUTH_INVALID_CREDENTIALS`
- `AUTH_TOKEN_EXPIRED`
- `AUTH_TOKEN_REVOKED`
- `AUTH_FORBIDDEN`
- `VALIDATION_ERROR`
- `NOT_FOUND`
- `CONFLICT`
- `CAPACITY_FULL`
- `CSV_PARSE_ERROR`
