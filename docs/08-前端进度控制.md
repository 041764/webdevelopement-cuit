# 前端进度控制（Vue 3 + Vite + TS，对接后端全量 API）

> 目标：这是一个作业/展示项目，追求“快速原型 + 风格扁平/现代/简约”，但要求 **后端 OpenAPI 中已有的接口必须全部在前端正确对接**。
>
> 单一事实来源：`docs/openapi.yaml`。

## 0. 成功标准（必须可验收）

| 类型 | 标准 | 例子（可观测） | Pass/Fail |
|---|---|---|---|
| Functional | 每个 OpenAPI endpoint 都有对应的前端调用路径（页面操作或开发工具页） | 点击“登录”触发 `POST /auth/login`，收到 200 后进入主界面 | 能触发且正确处理响应/错误 = Pass |
| Observable | 页面有明确的 Loading / Empty / Error 状态 | 401 自动刷新一次；刷新失败则强制退出并回到登录页 | 状态行为符合定义 = Pass |
| Coverage | 单测/集成测试覆盖边界场景 | refresh 并发 401 只发一次 refresh；失败不死循环 | 测试全部通过 = Pass |
| Integration | 本地启动后端，前端可完整走通核心流程 | 登录→活动列表→报名→取消；计划→新增条目→更新状态→追加进度 | 全流程可操作 = Pass |

## 1. 测试策略（每个模块完成必须带测试）

### 1.1 测试分层
- Unit（Vitest）：纯函数/状态/错误映射/请求组装（无 DOM 或轻量 DOM）
- Integration（Vitest + MSW）：组件交互 + API 请求（用 MSW 模拟后端响应/异常）
- E2E（Playwright）：关键业务路径的“冒烟 + 回归”

### 1.2 关键边界用例（全局）
- 401：access 过期 → 触发 refresh → 重新发起原请求
- 401：refresh 也失败 → 清空 token、跳转 `/login`
- 并发 401：多个请求同时 401 → 仅 1 次 refresh，其余排队重试
- 422：参数校验失败 → 表单字段级错误提示
- 403：无权限 → 明确提示 + 禁用入口
- 404：资源不存在 → 404 空态
- 网络错误/超时 → 可重试提示

## 3. API 覆盖矩阵（必须 100%）

> 说明：每个 endpoint 至少对应：
> - `src/api/<feature>.ts` 中的函数
> - 一个可触发的 UI（页面按钮/表单/开发工具页）
> - 单测或集成测试覆盖成功+失败（至少 1 个边界）

### 3.1 health / openapi
- [ ] `GET /health` → Dev 工具页（后端状态）
- [ ] `GET /openapi` → Dev 工具页（Swagger 链接）

### 3.2 auth
- [ ] `POST /auth/login` → 登录页
- [ ] `POST /auth/refresh` → Axios 拦截器自动调用

### 3.3 users

### 3.4 activities

## 4. 已知缺口/约束（必须显式记录）

- `docs/04-原型设计.md` 提到的 `GET /colleges` 在 `docs/openapi.yaml` 中 **不存在**。
  - 前端对 `collegeId`（报表筛选）将采用“手动输入 ID”的方式，直到后端补齐 colleges 相关接口。
- 部分接口入参需要 `classId`、`evaluateeUserId` 等 ID，但 OpenAPI 未提供查询/列表接口。
  - 展示项目策略：用“手动输入 ID”的表单字段；并在 UI 中标注“来自数据/数据库/导入结果”。
